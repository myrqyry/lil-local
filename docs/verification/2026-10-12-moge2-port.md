# MoGe-2 geometry port — 2026-10-12

## Scope and provenance

MoGe-2 was ported from the Veyax browser proof at Veyax commit
`a40a682` into the **existing**
`@litert-playground/depth-estimation` package. Depth Anything 3's
`DepthEstimationPipeline` and manifest remain unchanged.

Source model: https://huggingface.co/litert-community/MoGe-2-LiteRT
Immutable source revision: `6af93bb77c766c9c63aa364e51506a98cc35ccba`.
The adapter is original implementation code; the pretrained model and
conversion are MIT-licensed. The weight files are not committed.

## API

All through the public `@litert-playground/depth-estimation` entrypoint:

- `estimateMoGeGeometry(context, imageData, options?)`: accepts a caller-owned
  `ManagedLiteRtRuntimeContext` subset, uses its managed scheduler and
  caller-selected or automatic backend. Pinned FP16 WebGPU weights for
  WebGPU; FP32 weights for WASM. Explicit backends do not silently fall back.
- `moGeGeometryToDepthFrame(geometry, timestampMs?)`: produces canonical
  relative-depth `DepthFrame` preserving source size, frame ID,
  normalized source-to-depth UVs, model ID, resolved backend and near/far
  semantics.
- `releaseMoGeModels(runtime)`: releases only MoGe's two model entries;
  caller retains ownership of the shared runtime.
- Rich `MoGeGeometry`: affine points, surface normals, confidence mask,
  relative depth, raw scale, source shape, model revision and inference
  metadata.

Input: RGB normalized float32 NCHW `[1,3,448,448]`; output heads are two
`[1,448,448,3]` tensors (normals vs affine XYZ, differentiated via
unit-vector magnitude), `[1,448,448,1]` sigmoid mask and `[1,1,1,1]`
scale tensor. The WebGPU path performs async `tensor.moveTo('wasm')`
readback before copying CPU arrays, with explicit cleanup of all tensors.

Affine XYZ and predicted scale are **not automatically calibrated metric
world coordinates**. The derived depth is frame-relative; invalid pixels
are masked in the rich result. No live/continuous camera pipeline or
temporal depth stabilization is part of this port.

## Verified boundaries

- Focused package TypeScript typecheck: pass.
- Focused package Vitest: 19/19 pass (existing depth contracts, preprocessing,
  four-head decoding, mock shared-runtime calls, cancellation, tensor cleanup,
  canonical result conversion).
- Boundary tests: 16/16 pass.
- External consumer fixture imports the MoGe functions and type *through the
  package public entrypoint*, and the full compatibility lane can pack,
  install, typecheck and build the package.
- Fresh browser smoke from the **lil-tart depth package**:
  headless Linux Mint Chromium with WebGPU enabled through SwiftShader,
  real model load/run, GPU output readback, canonical depth conversion:
  `LILTART_MOGE_BROWSER_PASS=1`.
  Observed 602,112 float point-map values, 602,112 normal values,
  200,704 confidence mask values, finite predicted scale ~0.8655,
  valid fraction 1, correct source frame ID, canonical
  `higher-far` normalization.
- Veyax's earlier direct adapter was independently exercised on WebGPU and
  WASM/FP32. That is **not** separate evidence that the newly ported
  package's WASM path was executed in a browser.

The browser GPU was **software SwiftShader**, not a native RTX 2070 Super
performance measurement. The conversion's quantitative quality vs ground
truth, camera focal/shift metric recovery, and all video-frame cadence
claims remain unverified. Model files are fetched on demand.

## Consumer migration boundary

Veyax currently pins all Lil Tart packages to one Git revision. The
upstream commit containing this package must be remotely available
and adopted as a single revision across **all** Lil Tart dependencies
before changing Veyax's imports. Until then Veyax keeps its locally
validated adapter and Geometry Lab working. Do not introduce a
workspace-only path override or mixed-revision graph to shortcut this.

The native C++ HyperShaderFX plugin cannot import this TypeScript package;
it can later consume the same geometry contract through a native adapter.

## Gate

The authoritative final check is `pnpm verify` on the cleaned tree, with
typecheck, unit tests, package boundaries, packed-consumer compatibility,
conversion-asset validation, runtime qualification and builds.
